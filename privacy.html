Sovera is currently a public frontend prototype. This notice explains what happens in preview mode today and what changes when an owner connects the planned cloud features.

Current status: the live website has no Supabase project credentials configured. The sign-in screen is a temporary preview profile, not verified registration. Saved design concepts are kept in this browser's local storage. Do not use a real password, upload confidential designs or upload sensitive personal photos to the prototype.

1. Data in preview mode

The preview profile name and email are held in this browser tab session for the demo. Preview design objects are stored in local storage. They are not synced between accounts or devices and are not a secure vault. Someone with access to the same browser profile may be able to inspect local browser data. You can sign out or clear this site's browser data to remove preview session data; locally saved draft records may remain until the site's local storage is cleared.

2. Third-party page resources

The site currently loads fonts from Google Fonts, Three.js from a public CDN, and editorial reference images from Unsplash. When your browser requests these assets, those providers may receive connection data such as your IP address, browser headers and the requested URL under their own policies. Sovera does not control those third-party systems.

3. If cloud accounts are activated

When the owner configures Supabase, the intended account system will process email, account/profile details, designs, measurements, design visibility, likes, comments and reports. Full design payloads and original uploads are intended to remain owner-only through database row-level security and private Storage policies. Only a separately rendered watermarked preview and selected public metadata should appear in Explore after you explicitly publish it.

These controls are not active until the Supabase schema, Auth settings, Storage buckets and Edge Functions have been deployed and tested. A public key in the static website is not a secret; data safety depends on server-side roles and tested RLS policies.

4. Photo try-on and AI processing

The local photo overlay in preview mode stays in the browser. A future AI try-on request, once enabled, would upload the selected photo to temporary private storage and send it to the configured OpenAI image-edit service only after you check the consent box and request generation. The generated image is returned to your browser and is not automatically saved to your design library.

The integration is designed to remove the temporary uploaded original after processing, but failed network/storage cleanup can require support review. The AI result is a visual estimate, not a sizing, fit, tailoring or medical assessment. Review OpenAI's API data controls: provider safety review and retention rules may apply, and API image inputs can be retained for safety review in certain cases. Do not upload photos unless you understand and accept those conditions.

5. Public sharing and design privacy

Private designs should not appear in the public gallery. Publishing is intended to expose only a separate watermarked preview image and a limited set of display details—not the source pattern, full measurements or original photo. Public designs can still be copied, photographed or recreated by viewers. No website can guarantee that screenshots or external-camera captures are blocked.

6. Admin logs, moderation and reports

The planned admin dashboard records limited operational events such as design creation/publishing, moderation actions and AI request outcomes. The code is designed not to log photo content, passwords, full design JSON or full comment text into activity metadata. Moderation reports may contain the category and short details a reporter submits. Admin data is intended to be available only to verified roles through server-side functions.

A production retention schedule, contact channel, privacy jurisdiction, legal basis, and backup deletion policy must be set by the site owner before opening the real community. This prototype notice does not claim a certification or guarantee legal compliance.

7. Choices and contact

Preview users can avoid uploading photos and can keep designs local. When cloud features are activated, the intended controls are private-by-default drafts, explicit publish/unpublish, reporting and self-service account deletion. Account deletion should remove the account's source files and database account records, subject to separately retained moderation records, backups and provider/legal requirements.

For privacy questions, contact the Sovera site owner through the GitHub repository: Sovera GitHub repository. A dedicated privacy contact and final retention rules should be added before a production launch.
